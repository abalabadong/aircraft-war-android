# 开题任务书

项目名称：基于 Android 的飞机大战游戏迁移与网络功能扩展

## 一、项目概述

本项目以小组成员黄梓洋在《软件构造》课程中完成的 Windows 端飞机大战游戏为基础，将其迁移至 Android 平台，并在保留原有玩法的基础上，增加局域网双人积分竞赛与服务端排行榜功能。原项目已实现玩家飞机控制、多种敌机、不同射击方式、道具效果、难度选择、音效及本地排行榜。本项目计划适配手机触控操作、屏幕显示、音频播放和数据存储，使玩家能够在 Android 设备上完成单机游戏和联网竞赛。

项目实施过程中，将综合运用面向对象设计、设计模式、移动端界面开发、线程管理、网络通信和数据持久化等知识。通过区分可复用的游戏逻辑与依赖桌面平台的代码，完成软件的跨平台迁移，积累模块划分、接口设计、团队协作和测试调试经验。

## 二、原有功能迁移分析

### 1. 选择迁移哪位小组成员的代码，为什么？

本组选择迁移黄梓洋（学号：2024311608）的《软件构造》课程期末飞机大战项目。

该项目具有较完整的游戏功能，已实现多种敌机、Boss、不同弹道、火力增强、炸弹和冰冻等道具，以及音效与本地排行榜。在结构上，项目通过工厂创建敌机和道具，通过射击策略接口区分不同射击方式，通过观察者接口处理部分道具效果，并将排行榜数据访问接口与文件存储实现分离。这些结构能够为 Android 迁移及后续扩展提供基础。

与另一份代码相比，该项目的射击方式与道具玩法更加丰富，数据访问接口也更明确，有利于后续增加功能和替换存储方式。目前整理后的 47 个 Java 源文件已通过编译。迁移前已将英雄机初始生命值由 10000 调整为 100，并同步调整原有生命值测试；后续还将整理碰撞检测、计时和游戏状态管理等逻辑。

### 3. 需重新开发的模块及依据

| 模块 | 重新开发内容 | 原因 |
| --- | --- | --- |
| 界面与绘制 | 开始菜单、难度选择、游戏画面、排行榜和结束界面 | 原有 JFrame、JPanel 等 Swing 组件及 AWT 绘图代码依赖桌面平台，需要用 Android 界面与绘制方式实现 |
| 输入控制 | 将鼠标控制替换为手指拖动，并处理触控边界 | 手机端采用触屏操作，输入事件和操作习惯与桌面端不同 |
| 图片加载与屏幕适配 | 重新加载图片、计算显示比例，并统一渲染和碰撞坐标 | 原项目使用 BufferedImage、ImageIO 和固定窗口尺寸，需适配不同手机的屏幕比例及分辨率 |

| 游戏循环与生命周期 | 游戏更新、绘制调度、暂停恢复、退出和重新开始 | 原有 Timer 及零散线程未统一管理，需避免页面退出后仍继续更新，并使道具计时与暂停行为一致 |
| 本地持久化 | 成绩和游戏设置的读取、保存、删除 | 原项目依赖工程工作目录下的文本文件，移动端应通过应用内部存储或本地数据库管理数据 |
| 网络通信 | 联网房间、实时状态交互、成绩上传及服务端榜单查询 | 原项目尚无这些网络业务，需要新增客户端通信模块和配套服务端 |

## 三、新增网络功能设计

### 1. 局域网双人积分竞赛

功能内容：玩家可以创建或加入房间，两人准备完成后由服务器通知开始游戏。双方分别操作自己的飞机，客户端显示对手的分数、生命值和游戏结束状态，按照约定的计分与结束规则判定胜负。双方独立进行游戏，实时比较成绩；同一地图中的位置、子弹及碰撞同步不列入本项目的基本范围。

设计原因：单机游戏缺少玩家之间的互动，联网竞赛能够增加竞争性，也能够结合课程要求实践连接管理、消息传输、线程协作和异常处理。

简要技术思路：首版在同一 Wi-Fi 下使用一台电脑运行服务端，两台 Android 设备通过服务器的局域网地址连接。采用客户端—服务器结构，使用 TCP 长连接传输房间操作、准备、开始、分数、生命值和结束等消息。消息采用统一的数据格式，并设置明确的消息边界。服务端管理房间和比赛状态，客户端在独立线程中收发消息，再将展示数据交给界面更新。通过房间编号、玩家标识、心跳与超时判断处理匹配、断线和退出，避免对手断开后比赛一直等待。

### 2. 服务端排行榜与成绩上传

功能内容：玩家完成游戏后，可以将昵称、分数、难度和完成时间上传至服务器，并查询相应难度的服务端排行榜。本地成绩仍保留，网络不可用时不影响单机游戏。

设计原因：原有排行榜仅保存本机记录，无法比较不同设备上玩家的成绩。服务端排行榜能够增强游戏的持续参与感，并用于实践网络接口调用、服务端数据管理和客户端异常处理。

简要技术思路：首版与联网竞赛服务端一同部署在局域网电脑上，提供基于 HTTP 的成绩提交和榜单查询接口，采用 JSON 传输数据，并将成绩保存到数据库中，按难度分类、按分数排序。Android 客户端异步执行网络请求，显示加载结果或失败提示。上传时为记录生成唯一标识以避免重复提交，服务端检查必填字段和分数范围。课程原型先实现正常使用流程与基础校验，完整反作弊机制不列入本阶段范围。

实施顺序：先完成 Android 单机最小流程，再尽早验证两台设备连接并交换分数，随后完成房间流程和服务端排行榜，最后完善界面与音效。公网部署作为进度允许时的可选扩展，不作为基础验收目标。
