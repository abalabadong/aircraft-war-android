# 开题任务书

项目名称：基于 Android 的飞机大战游戏迁移与网络功能扩展

## 一、项目概述

我们计划将黄梓洋在《软件构造》课程中完成的 Windows 端飞机大战游戏迁移到 Android 平台，并增加局域网双人积分竞赛和服务端排行榜。原项目已有玩家飞机控制、多种敌机、不同射击方式、道具、难度选择、音效和本地排行榜。迁移时将保留这些玩法，重新适配手机触控、画面显示、音频播放和数据存储，使玩家可以在 Android 设备上进行单机游戏和联网竞赛。

这次实践需要解决的主要问题，是如何保留原有游戏逻辑，同时替换依赖桌面平台的实现。我们将在开发中运用面向对象设计和设计模式，学习 Android 界面开发、线程管理、网络通信与数据持久化，并通过两人协作完成模块划分、接口对接和测试调试。

## 二、原有功能迁移分析

### 1. 选择迁移哪位小组成员的代码，为什么？

本组选择黄梓洋（学号：2024311608）的《软件构造》课程期末飞机大战项目作为迁移基础。

该项目已实现多种敌机、Boss、不同弹道、火力增强、炸弹、冰冻、音效和本地排行榜。代码中使用工厂创建敌机和道具，通过射击策略接口区分弹道，通过观察者接口处理部分道具效果，排行榜也分出了数据访问接口和文件存储实现。迁移时可以沿用这些接口和游戏规则，分别替换绘制、存储等平台相关代码。

比较两人的项目后，我们认为这份代码的射击方式和道具玩法更丰富，数据访问接口也更明确，适合继续增加功能。目前，整理后的 47 个 Java 源文件已通过编译。英雄机初始生命值已从 10000 调整为 100，相应的生命值测试也已修改。后续将继续整理碰撞检测、计时和游戏状态管理。

### 2. 可复用模块及依据

| 模块 | 可复用内容 | 复用依据与调整 |
| --- | --- | --- |
| 游戏对象模型 | 飞机、子弹、道具的继承关系，以及坐标、速度、生命值、伤害和有效状态等数据 | 这些内容描述的是游戏对象和规则。去掉图片类型、桌面窗口等依赖后，可以继续使用 |
| 移动与碰撞逻辑 | 位置更新、边界判断和碰撞计算 | 计算过程不依赖桌面界面。需要先修正现有碰撞遍历结构，再适配手机端的坐标和对象尺寸 |
| 敌机与道具工厂 | 工厂接口、创建流程，以及敌机和道具类型 | 创建对象的职责可以保留，生成位置及尺寸参数按手机游戏区域调整 |
| 射击策略 | 直射、双线、散射、环射等策略接口和弹道计算 | 弹道主要根据位置、速度和方向计算，可以在 Android 端沿用 |
| 道具与计分规则 | 加血、火力增强、炸弹、冰冻、敌机分值和道具掉落规则 | 规则本身可以保留，音效调用、效果计时和状态恢复需要重新适配 |

| 图片与音频素材 | 飞机、背景、子弹、道具图片及音频文件 | 素材可以继续使用，但需要调整资源目录、加载方式和显示比例 |

复用时主要保留规则、接口和算法，各个类仍需检查并清理平台依赖，不能直接全部复制到 Android 工程中。

### 3. 需重新开发的模块及依据

| 模块 | 需要完成的工作 | 原因 |
| --- | --- | --- |
| 界面与绘制 | 重新实现开始菜单、难度选择、游戏画面、排行榜和结束界面 | 原有 JFrame、JPanel 等 Swing 组件和 AWT 绘图代码用于桌面程序，需要改用 Android 的界面与绘制方式 |
| 输入控制 | 将鼠标操作改为手指拖动，处理触控边界 | 手机的输入事件和操作方式与电脑不同 |
| 图片加载与屏幕适配 | 重新加载图片、计算显示比例，统一绘制和碰撞坐标 | 原项目使用 BufferedImage、ImageIO 和固定窗口尺寸，需要适配不同手机的屏幕比例与分辨率 |
| 音频播放 | 实现背景音乐、Boss 音乐、命中和爆炸等音效的播放与释放 | 原有 javax.sound.sampled 实现需要替换，并处理应用切入后台时的音频状态 |
| 游戏循环与生命周期 | 管理更新、绘制、暂停、恢复、退出和重新开始 | 原有 Timer 和零散线程需要统一管理，避免页面退出后继续运行，同时使道具计时与暂停状态一致 |
| 本地持久化 | 保存、读取和删除成绩及游戏设置 | 原项目在工程工作目录中读写文件，移动端需要改用应用内部存储或本地数据库 |
| 网络通信 | 新增房间、状态交互、成绩上传和服务端榜单查询 | 原项目没有网络业务，需要开发客户端通信模块和配套服务端 |

## 三、新增网络功能设计

### 1. 局域网双人积分竞赛

玩家可以创建或加入房间。两人准备后，服务器通知双方开始游戏。每人操作自己的飞机，同时查看对手的分数、生命值和游戏结束状态，最后按约定的计分与结束规则判定胜负。双方各自运行游戏，实时比较成绩；同一地图中的位置、子弹和碰撞同步不在本次基本开发范围内。

设计这项功能，是希望在单机玩法上加入两名玩家之间的竞争，也借此练习连接管理、消息传输、线程协作和异常处理。

首版使用同一 Wi-Fi 下的一台电脑运行服务端，两台 Android 设备通过局域网地址连接。客户端与服务端使用 TCP 长连接，传输房间操作、准备、开始、分数、生命值和结束等消息，并约定统一的数据格式和消息边界。服务端管理房间和比赛状态，客户端在独立线程中收发消息，再更新界面显示。通过房间编号和玩家标识区分比赛与参与者，配合心跳和超时判断处理匹配、断线及退出，避免一方断开后另一方一直等待。

### 2. 服务端排行榜与成绩上传

游戏结束后，玩家可以将昵称、分数、难度和完成时间上传到服务器，查询相应难度的排行榜。本地成绩仍然保留，网络不可用时可以继续单机游戏。

原有排行榜只能查看本机记录。增加服务端排行榜后，不同设备上的玩家就能比较成绩，也能让玩家在后续游戏中尝试提高排名。开发这项功能时，我们将练习网络接口调用、服务端数据管理和请求失败时的处理。

排行榜首版与联网竞赛服务端一起运行在局域网电脑上。服务端提供 HTTP 成绩提交和榜单查询接口，以 JSON 传输数据，将成绩保存到数据库中，按难度分类、按分数排序。Android 客户端异步发起请求，显示加载结果或失败提示。每条上传记录使用唯一标识，避免重复提交；服务端检查必填字段和分数范围。本阶段完成正常流程和基础校验，暂不实现完整的反作弊机制。

开发时先完成 Android 单机的最小流程，再尽早验证两台设备能否连接并交换分数，随后完成房间流程和服务端排行榜，最后完善界面与音效。公网部署视进度作为扩展内容，不列入基础验收目标。

## 五、预期结果

1. 完成可在 Android 设备或模拟器上安装运行的飞机大战应用，支持触控移动、自动射击、敌机生成、碰撞判定、道具、计分、难度选择和游戏结束。
2. 完成菜单、游戏画面、音效和本地排行榜的适配，正确处理暂停、恢复和退出。
3. 实现局域网双人积分竞赛，支持创建或加入房间、准备开始、双方状态展示和结果判定，并在断线或退出时给出提示。
4. 实现成绩上传和服务端排行榜查询。网络不可用时，单机游戏和本地成绩记录仍可使用。
5. 提交 Android 工程源码、配套服务端源码及启动说明、可安装的 APK、测试记录和结题报告。演示内容包括单机流程，以及同一 Wi-Fi 下两台设备的积分竞赛、成绩上传和榜单查询。
